# VPN Маркетплейс — сайт

Сайт-агрегатор VPN-сервисов: каталог из 50+ провайдеров карточками (цена,
заявленная скорость, платформы, фишки) + автоматическая фоновая проверка
доступности сайта каждого провайдера (пинг/uptime), которая обновляет статус
на сайте. Тот же периодический прогон синхронизирует каталог из
`src/data/services.ts` в базу — правки файла подхватываются на следующем
плановом запуске без ручного вызова seed.

## Как это на самом деле работает (важно прочитать)

Полностью автоматически «найти все существующие VPN-сервисы в интернете» и
протестировать их реальную скорость через VPN-туннель — невозможно без
партнёрства/API/аккаунта в каждом сервисе. Поэтому архитектура такая:

- **Каталог провайдеров курируется вручную** — [`src/data/services.ts`](src/data/services.ts).
  Цена, «заявленная скорость», фичи и т.д. — это данные из маркетинга
  провайдера, а не измерения. Обновляйте файл, когда провайдер меняет тарифы.
- **Доступность и задержка проверяются автоматически и по-настоящему** —
  [`src/lib/checker.ts`](src/lib/checker.ts) реально делает HTTP-запрос на
  сайт провайдера, измеряет время ответа и помечает сервис как
  online/offline. Это проверка «жив ли сайт провайдера», а не скорость VPN.
- Периодически запускается [`scripts/check-services.ts`](scripts/check-services.ts)
  (через cron/systemd на своём сервере, либо `vercel.json` → Vercel Cron
  дергает `/api/cron/check`) — за один прогон он (1) синхронизирует каталог из
  `src/data/services.ts` в базу и (2) обновляет `status`, `latencyMs`,
  `lastCheckedAt` для каждого сервиса. Главная страница читает уже посчитанные
  значения.

## Стек

- Next.js 14 (App Router) + TypeScript + Tailwind CSS
- PostgreSQL + Prisma ORM
- Шрифт: системный стек `-apple-system, BlinkMacSystemFont, …` — на
  устройствах Apple рендерится как SF Pro Display/Text (сам шрифт Apple не
  распространяет для встраивания на произвольные сайты, поэтому файл шрифта
  не подключается — используется системный рендеринг)

## Быстрый старт

```bash
cd vpn-site
npm install
cp .env.example .env      # укажите DATABASE_URL и CRON_SECRET
docker compose up -d      # локальный Postgres (или укажите свой DATABASE_URL)
npm run prisma:migrate    # создаст таблицы
npm run db:seed           # заполнит каталог из src/data/services.ts
npm run check:services    # (опционально) сразу проверить доступность сайтов
npm run dev                # http://localhost:3000
```

## Как добавить/изменить VPN-сервис

Отредактируйте [`src/data/services.ts`](src/data/services.ts) и задеплойте
(или локально выполните `npm run db:seed` / `npm run check:services`).
Каталог также сам подтянет изменения на следующем плановом прогоне
`/api/cron/check` — вручную дёргать seed не обязательно.

## Монетизация через партнёрские ссылки

Сейчас кнопка «Перейти на сайт» у каждого сервиса ведёт на обычный `websiteUrl`
(поле `referralUrl` в схеме уже есть, но пустое). Зарегистрироваться в
партнёрской программе провайдера и получить свою реферальную ссылку может
только владелец сайта лично — это создание аккаунта со своими налоговыми и
платёжными данными, такое я сделать не могу. Как это включить:

1. Зарегистрируйтесь в партнёрской программе нужных провайдеров, например:
   NordVPN ([партнёрка](https://nordvpn.com/affiliates/)), ExpressVPN
   ([партнёрка](https://www.expressvpn.com/affiliates)), Surfshark
   ([партнёрка](https://surfshark.com/affiliate-program)), CyberGhost, PIA,
   Proton VPN — у большинства крупных провайдеров такие программы есть, ищите
   раздел «Affiliates»/«Partners» на их сайте.
2. Пропишите полученную ссылку в поле `referralUrl` нужного сервиса в
   [`src/data/services.ts`](src/data/services.ts).
3. Задеплойте — карточка и кнопка на странице сервиса автоматически начнут
   вести по партнёрской ссылке, менять код нигде больше не нужно.

## Жалобы на устаревшие цены/описания

На странице каждого сервиса есть кнопка «Сообщить об ошибке» — она пишет в
таблицу `PriceReport` через `POST /api/report`. Посмотреть накопленные
сообщения:

```bash
curl -s https://www.vpnmarket.online/api/admin/reports -H "x-cron-secret: $CRON_SECRET"
```

## Как настроить автопроверку в проде

**Вариант A — Vercel:** задеплойте на Vercel, добавьте переменные окружения
`DATABASE_URL` (пул) и `DATABASE_URL_UNPOOLED` (прямое подключение — их
автоматически создаёт интеграция Neon) и `CRON_SECRET`. `vercel.json`
содержит cron-задачу на `/api/cron/check`. **Hobby-план Vercel разрешает cron
не чаще раза в сутки** — расписание стоит на ежедневный запуск (`0 6 * * *`).
Для более частых проверок (например, каждые 30 минут) используйте
[`.github/workflows/check-services.yml`](.github/workflows/check-services.yml) —
он дёргает тот же `/api/cron/check` через GitHub Actions (бесплатно), нужно
только добавить в Secrets репозитория `SITE_URL` и `CRON_SECRET`.

**Вариант B — свой сервер/VPS:** добавьте в crontab:

```
*/30 * * * * cd /path/to/vpn-site && npm run check:services >> /var/log/vpn-check.log 2>&1
```

## Миграции схемы БД

Автоматический `prisma migrate deploy` в build-шаге Vercel **намеренно не
используется на постоянной основе** — через пулер Neon (PgBouncer)
advisory-lock, которым пользуется Prisma Migrate, периодически подвисает и
роняет билд без реальной причины (даже с `directUrl` на прямое подключение).

Если меняете `prisma/schema.prisma`, самый надёжный вариант — временно
добавить в `package.json` шаг `"build": "prisma db push --skip-generate &&
next build"`, задеплоить один раз, дождаться успешного билда (это применит
схему через build-окружение Vercel, у которого есть доступ к базе — в
отличие от многих локальных песочниц, где порт 5432 наружу закрыт), затем
вернуть `"build": "next build"` обратно. `db push` не создаёт файл миграции
в `prisma/migrations/` — для аддитивных изменений (новая таблица/колонка)
это ок, но `git diff` в `prisma/migrations/` не покажет историю.

Есть и альтернатива через `migrate deploy` с прямым подключением — иногда
срабатывает, иногда так же подвисает на локе:

```bash
DATABASE_URL="$DATABASE_URL_UNPOOLED" npx prisma migrate deploy
```

## Известные ограничения

- «Заявленная скорость» — маркетинговый показатель провайдера, не измерение.
- Проверка идёт до сайта провайдера (HTTP), а не через сам VPN-туннель —
  честный показатель «жив ли провайдер», но не «какая скорость в VPN».
- Каталог не пополняется сам новыми провайдерами — добавление нового VPN в
  список делает человек через `src/data/services.ts`; периодически
  обновляются только статус/задержка существующих записей.
